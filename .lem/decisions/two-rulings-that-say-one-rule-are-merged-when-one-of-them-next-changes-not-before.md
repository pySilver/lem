# Two rulings that say one rule are merged when one of them next changes, not before

The owner said the count of files in `docs/rulings/` confused him, and asked whether the rulings
can "eventually" become a plain list. The list exists: each file's title is its rule, and
`AGENTS.md` holds the titles, one linked sentence each, under the heading of its group.

An audit on 2026-11-21 read all 129 files the folder then held. It found 17 narrow rulings, and
16 groups whose rulings say one rule, where a merge would lose nothing. The groups are below, by
file stem, so that the read is not lost.

A merge is a new ruling in the owner's name, so each group needs his yes. By the rule for a
ruling that replaces another, the new file takes the old ones whole, so the words stay and only
the count of sentences in `AGENTS.md` falls: by 22, the 38 files of the groups less one sentence
for each group (a count from the list, not a size in bytes). No failure from the count is known:
an agent finds a ruling by its sentence in `AGENTS.md` or by its `area:` line
(`skills/lem-gate/references/judge.md`).

So the session merges a group when one of its rulings next changes and he is asked anyway, and
not before. It is open to him.
