Type a request in plain words, and get a pull request whose first line says green or not green.

For a developer who works alone, and for a team on Linear or GitHub Issues.

Agents plan, build, test and review the change in your repository. Lem is a plugin for Claude Code that works closely with agterm.

claude plugin marketplace add pySilver/lem --scope project
claude plugin install lem@lem --scope project

Lem needs agterm. Run the two lines in your repository, then type /lem init.

01 · How a task goes

A task needs you three times at most

Lem reads each request, and tells you its type and its track in one line. Then the task needs you at three points at most.

  1. The shape On the standard track, you answer the interview, and say yes to the acceptance criteria.
  2. A circuit breaker A task stops, and leaves a document for you.
  3. A pull request that the merge agent calls you for You read its review, and merge.

On the fast track, only the third touch can come. When Lem needs you tells you more.

Fast track

  1. Your request
  2. One builder makes the change
  3. Checks and one read
  4. Pull request the merge agent reads it
  5. Merge when the merge agent calls you

Standard track

  1. Your request
  2. Interview you answer
  3. Acceptance criteria you say yes
  4. Plan and build a builder for each part
  5. Checks and a review
  6. Pull request the merge agent reads it
  7. Merge when the merge agent calls you

You can act here.

Each request opens a task in an agterm session of its own. The fast track is for one plain change with no open question: a typo, a rename, the fix of one rule. One builder makes it, and nothing waits for you. When another person wrote the ticket, its one criterion waits for your yes first.

The standard track is for every other request. The interview runs in the session of the task, one question at a time, each with its guess. Nothing builds before your yes to the acceptance criteria, unless you are away or the task runs at night. Then the pull request is not green.

The build asks you nothing. A ladder of agents decides each choice, and the pull request lists each one with its reason. Only a circuit breaker stops a task, with a document for you.

A fresh merge agent reads each pull request. It merges a green one that is not careful, and calls you for the rest.

02 · Guarantees

What you can rely on

  • Nothing merges before your tests pass and an agent that did not build the change reviews it.
  • After an interview, nothing builds before your yes to the acceptance criteria, unless you are away or the task runs at night.
  • Every reviewer reads a change that can affect what you said must never go wrong, and you merge it.
  • A step that nobody can undo stops the task, and waits for you.
  • Lem never pushes over a commit that it did not push.

A change that can affect what you said must never go wrong is careful: every reviewer reads it, and you merge it.

Green, or not green with each reason

The first line of each pull request says green or not green. A pull request is not green when, for example:

  • your tests got less strict;
  • the review left a must-fix after two rounds;
  • a criterion changed during the build;
  • a decision went past the personas.

With branch.land = "owner", you merge each pull request. Green means you can merge without a read.

03 · The board

Every task in one place, on every screen

The board puts each task in a column by who acts next, and it updates by itself. The same board opens in agterm, in a browser and on your phone.

  • Tasks Each task in the column of who acts next: you, a builder, the checks, or done.
  • Waits for you One row for each task, with what you do: read a breaker, approve the criteria, read a merge review or merge. A task with two or more things is one stack, which opens on a click.
  • Backlog The work for later, in groups by its worth. The proposals of the morning's retro that a reviewer agent passed come first, for you to start or drop.
  • Activity Where the time went, and every event.

A task opens with five tabs: Overview Criteria and decisions Checks and review Timeline Artifacts

04 · On your phone

Follow the work away from your desk

The board opens on your phone through Tailscale, a private network of your own devices. Only your Tailscale login gets access.

Add the board to the Home Screen. Lem then sends a notification each time something starts to wait for you.

Two computers, one address. /lem serve join HOST shows the repositories of a second computer on the board of the first.

The computer must be awake. Lem needs Tailscale only for another device.

Set it up one time

  1. Install Tailscale on the computer and on the phone, with one account.
  2. In the Tailscale admin console, turn on MagicDNS and HTTPS.
  3. Type /lem serve tailscale in Claude Code.
  4. On the phone, open the address that Lem gives, and select "Add to Home Screen".
  5. Open Lem from the Home Screen, and turn on notifications with one tap.

05 · Many tasks at once

Many tasks build and land at the same time

Each task has its own worktree. A task waits for another task only when it needs the result of that task, or when you put that task first.

  • A session for each task Type your next request in any session. It opens a session of its own, while the other tasks build.
  • Checks under your load limit The checks start only while the load of your computer is below 40, or below the limit that you set. The task that waits longest starts first. A task that another task waits for starts before it.
  • One merge at a time Lem merges one task at a time. When the base branch moved, the merge agent reads what moved, and Lem runs the checks again only when the agent asks.

06 · Your repository

Lem learns your repository

Lem keeps what it learns of your repository in four files. Each is a file in your repository's git.

  • .lem/profile.md The product.
  • .lem/personas/ The people that a change affects.
  • .lem/lessons.md Your corrections of how an agent does a step in this repository.
  • docs/rulings.md Your decisions about what the product does, which no agent reopens without asking you.

A second expert. Codex is optional and highly recommended. With it, a second model family reviews the larger changes and answers as a second expert.

What Lem keeps lists every file, in git and on your computer.

07 · Teams

Start from a ticket

Connect Linear or GitHub Issues to Lem. Then a ticket is the request of a task.

  • Linear Type /lem new ABC-12 in Claude Code. The ticket is the request, and Lem uses the branch name from Linear. Start a task from a ticket
  • GitHub Issues Type /lem new 42 in Claude Code. The text of the issue is the request. Start a task from an issue

A team shares the settings in git, the tickets and the pull requests. Each developer has their own board, with the tasks on their own computer.

08 · Install

Start in your repository

At the root of your repository:

claude plugin marketplace add pySilver/lem --scope project
claude plugin install lem@lem --scope project

Then start Claude Code in agterm there, and type /lem init. Answer three questions, read Lem's page, and type "land". Then type your first request.

/lem init checks each tool that Install lists. The main tools:

  • agterm
  • Claude Code
  • git
  • Python 3.11 or newer
  • revmux
  • cronn
  • GitHub CLI
  • Codex, highly recommended
  • Tailscale, for your phone

Each person installs Lem. Git shares .lem/settings.toml; ~/.config/lem/ holds yours. Newer settings stop an older Lem. To remove Lem, read Remove.

Updates bring the newest release, which repairs a bad one. Auto-update starts off; /plugin turns it on under Marketplaces. claude plugin list shows your release, which a session keeps until it ends.
